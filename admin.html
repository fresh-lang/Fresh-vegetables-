Referral reward policy

  • ₹5 one-time bonus for the referrer after the referred customer's first eligible order is delivered and payment is verified.
  • Additional ₹10 for each complete ₹1,000 of net eligible merchandise value on each eligible referred order (e.g. ₹999 = ₹0; ₹1,000 = ₹10; ₹2,000 = ₹20).
  • Net eligible merchandise value excludes delivery fees, discounts, cancelled items and refunded amounts.
  • Rewards start as PENDING_REVIEW; Admin approves after checking order and fraud signals.
  • One order can generate rewards only once. No reward for self-referral, duplicate customer identity, cancelled, unpaid or refunded orders.
  • Wallet is store credit for future Fresh Veggie purchases; it is not cash or a bank balance.

Admin approval checklist

  1. Confirm referred customer is a new customer with verified phone number.
  2. Check referral attribution was locked at sign-up/first order and not edited later.
  3. Confirm delivered status and verified payment (or COD cash collected).
  4. Review duplicate phone, repeated address/payment account and suspicious order patterns.
  5. Approve or reject the reward with an admin reason. Record actor, timestamp and order ID in immutable ledger.

Order & wallet statuses

Order: RECEIVED → PAYMENT_PENDING / COD_PENDING → PAID / COD_COLLECTED → PACKING → OUT_FOR_DELIVERY → DELIVERED.

Reward: PENDING_REVIEW → APPROVED → CREDITED. Or REJECTED / REVERSED for refund/chargeback.

Wallet: availableBalance and pendingBalance must be computed from server-written ledger entries, never trusted from client input.

Fraud protection

  • Require verified mobile number (OTP) for referrer and referred customer.
  • Only one referral attribution per new customer; lock it once the account is created/first order begins.
  • Block self-referrals using same verified phone/customer UID; flag repeated device, address, payment instrument or unusual referral bursts for manual review.
  • Rate-limit referral code attempts and order creation.
  • Use idempotency keys / unique reward IDs so retries cannot duplicate credits.
  • Do not rely on browser, QR screenshot, UTR typed by customer, or client-sent order amount as proof of payment.
  • Keep an audit trail; admin cannot edit or delete historical ledger entries.
